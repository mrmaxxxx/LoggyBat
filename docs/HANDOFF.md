# LoggyBat — устройство, сборка, установка

LoggyBat — виджет WidBar для пользователей беспроводной техники Logitech:
заряд всех устройств, которые G HUB показывает с батареей. Нужен запущенный
Logitech G HUB. Техника, которую G HUB не видит, не поддерживается.
Устройства разработчика (G502 X PLUS, PRO X Wireless) — тестовые, в коде к ним
ничего не привязано.

## Как это работает

```
Logitech G HUB (lghub_agent, ws://localhost:9010)
        │  WebSocket, JSON, опрос каждые 10 с
        ▼
LoggyBat.exe (процесс виджета, WinUI 3) ──► WidBar рисует его на панели задач
```

### Что видно

- **Панель:** не больше двух устройств, например `🖱 92%   🎧 69%`.
  Порядок: мышь → гарнитура → клавиатура → остальные; внутри типа — по названию,
  затем по текущему id G HUB. От заряда порядок не зависит.
  Иконки: 🖱 мышь, 🎧 гарнитура, ⌨ клавиатура, 🔋 остальные. `⚡` — зарядка,
  `—` — нет свежих данных. Пока ни одно устройство не найдено: `🔋 —`.
- **Flyout:** все устройства с батареей, с прокруткой, если не помещаются.
  Под каждым: `Ответ G HUB: 21:42:22` (время **получения ответа** — G HUB не
  сообщает время измерения) или `Нет данных: <причина>`.
  Без устройств — одно из состояний: «Подключение к G HUB…»,
  «Нет данных: G HUB не запущен», «Устройства с батареей в G HUB не найдены»,
  «Нет данных: ошибка списка устройств G HUB (…)».
- Названия берутся из G HUB. Одинаковые модели получают номера «(1)», «(2)»;
  между сеансами номера могут поменяться.

### Список устройств ([DeviceList.cs](../src/LoggyBat/DeviceList.cs))

- В список попадают устройства с `capabilities.hasBatteryStatus = true`.
- Постоянного ID устройства в G HUB нет, поэтому строки сопоставляются только
  по текущему `devNNNNNNNN` и только внутри одного соединения.
  После переподключения список строится заново — дублей из-за смены id нет.
- Устройство есть, но заряда нет (например, выключенная гарнитура) →
  строка `—` с причиной от G HUB.
- Устройство в списке, но не `ACTIVE` → строка `—`: для `NOT_CONNECTED`
  (так G HUB показал выключенную мышь LIGHTSPEED) — «не подключено (выключено?)»,
  для остальных состояний — «не активно в G HUB».
- Устройство исчезло из списка G HUB → строка `—` «исчезло из списка G HUB»
  не дольше 60 с, затем удаляется. Если за это время появился новый id той же
  модели, старая строка удаляется сразу.
- G HUB недоступен → последние известные строки показываются как `—` с причиной,
  пока новое подключение не даст свежий список.

### Подключение ([GHubClient.cs](../src/LoggyBat/GHubClient.cs))

- Один управляющий цикл и одно соединение; один цикл чтения на соединение;
  отправки под блокировкой; ответы сопоставляются по `msgId`.
- Каждый опрос: `GET /devices/list` → `GET /battery/<id>/state` для каждого
  устройства. Ответ-ошибка по одному устройству не трогает остальные.
- После подключения виджет подписывается (`SUBSCRIBE`) на `/devices/state/changed`
  и `/battery/state/changed`. Любое такое событие будит тот же цикл, и он сразу
  делает обычный опрос. Содержимое события не используется — только как сигнал.
  Пачка событий объединяется в один повторный опрос (одноместный сигнал), опросы
  никогда не идут параллельно. Опрос раз в 10 с остаётся подстраховкой.
- Тайм-аут каждого запроса 5 с. Нет ответа или обрыв → соединение закрывается,
  переподключение через 2, 4, 8 … 30 с.
- Пауза больше 40 с между опросами (сон Windows, скрытый виджет) →
  принудительное переподключение, даже если сокет «выглядит открытым».
- Пока виджет скрыт и flyout закрыт, опроса нет.
- Заряд показывается, только если для этого устройства последний ответ
  успешный и ему меньше 40 с.

### Лог

`loggybat.log`, пишется только при смене состояния, до 256 КБ (+ `.old`).
Внутри MSIX Windows перенаправляет его в папку пакета. Открыть:

```powershell
explorer "$env:LOCALAPPDATA\Packages\$((Get-AppxPackage Max.LoggyBat).PackageFamilyName)\LocalCache\Local\LoggyBat"
```

Если папки нет — посмотреть `%LOCALAPPDATA%\LoggyBat`.

## Идентичность

| Что | Где | Значение |
|---|---|---|
| WidBar Plugin ID | `MainPlugin.Id`, `WidBarPluginId` в `LoggyBat.csproj`, `Package.appxmanifest` — должны совпадать | `com.mrmaxxxx.loggybat` |

| Publisher | `Package.appxmanifest`, должен совпадать с сертификатом | `CN=Max` |

Смена любого из них = для Windows/WidBar это новое приложение.

## Версия

`1.1.<номер запуска workflow>.0`. Номер запуска (`github.run_number`) растёт на 1 при
каждом запуске workflow «Build LoggyBat» — и вручную, и по push в `loggybat`.
CI записывает версию в `Package.appxmanifest` и в `WidBarPluginVersion` перед сборкой.
В репозитории стоит `1.1.0.0` — это только заглушка.

Новая версия ставится поверх старой, если совпадают Identity, Publisher
и сертификат. Сохраняется ли при этом размещение виджета в WidBar — ещё не проверено.

## Сертификат (один раз, этап разработки)

Самоподписанный сертификат `CN=Max` и ручная установка `.cer` в «Доверенные лица» —
**временная схема для разработки и тестов**, не способ установки публичной версии:
другие пользователи не должны доверять чужому самоподписанному сертификату.
Для публичного выпуска нужно отдельно выбрать Microsoft Store (Store сам подписывает
пакет) или доверенный сертификат подписи кода. Тогда же, вероятно, сменятся
Identity и Publisher — это будет новое приложение для Windows.

1. Создать сертификат на своём компьютере (обычный PowerShell, не от администратора):
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\New-SigningCertificate.ps1
   ```
   Скрипт дважды спросит пароль (от 12 символов) и создаст папку `%USERPROFILE%\LoggyBat-signing`:
   `LoggyBat-signing.pfx` (закрытый ключ под паролем, AES-256 — хранить, никому не отдавать,
   не класть в репозиторий) и `LoggyBat.cer` (публичный). Ключ и пароль скрипт не выводит,
   папку внутри репозитория не принимает, существующий ключ не перезаписывает.
   Сделать резервную копию `.pfx` и запомнить пароль: без них не будет обновлений.
2. Скопировать ключ в буфер обмена в виде Base64:
   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("$HOME\LoggyBat-signing\LoggyBat-signing.pfx")) | Set-Clipboard
   ```
   GitHub → репозиторий → Settings → Secrets and variables → Actions →
   New repository secret:
   - `SIGNING_PFX_BASE64` — вставить из буфера обмена;
   - `SIGNING_PFX_PASSWORD` — пароль из шага 1.
3. Сразу очистить буфер обмена **и его журнал** (Win+V хранит копии):
   Win+V → «Очистить все» (или Параметры → Система → Буфер обмена → Очистить).
4. Доверять сертификату (PowerShell **от администратора**):
   ```powershell
   Import-Certificate -FilePath "$HOME\LoggyBat-signing\LoggyBat.cer" -CertStoreLocation Cert:\LocalMachine\TrustedPeople
   ```

Без секретов сборка падает на шаге «Sign package» с понятной ошибкой.
Если `.pfx` потерян, обновления поверх установленной версии станут невозможны:
понадобится новый сертификат и переустановка.

## Сборка

GitHub → Actions → «Build LoggyBat» → Run workflow → ветка `loggybat`
(или просто push в `loggybat`). Через ~5 минут скачать артефакт `LoggyBat-x64`
(хранится 7 дней) и распаковать.

## Установка и обновление (тестовая сборка)

1. Закрыть LGSTrayBattery и убрать его из автозагрузки
   (Диспетчер задач → Автозагрузка → LGSTrayGUI → Отключить).
2. Первый раз: удалить старый «Logitech Battery» (только по договорённости):
   ```powershell
   Get-AppxPackage Max.LogitechBattery.Widget | Remove-AppxPackage
   ```
3. Установить: двойной щелчок по `LoggyBat.Package_1.1.N.0_x64.msix` в распакованной папке,
   либо
   ```powershell
   Add-AppxPackage -Path "<путь>\LoggyBat.Package_1.1.N.0_x64.msix"
   ```
4. WidBar → Layout → Refresh → добавить LoggyBat.

Обновление: шаги 3–4 с новой сборкой (шаг 4 — только если виджет пропал).

## Откат

- Вернуть старое приложение:
  ```powershell
  Get-AppxPackage Max.LoggyBat | Remove-AppxPackage
  Add-AppxPackage -Path "Z:\CLAUDE\LoggyBat (PC)\LogitechBattery-x64\WidBarWidget1 (Package)_1.0.0.0_x64_Test\WidBarWidget1 (Package)_1.0.0.0_x64.msix"
  ```
  Его сертификат `CN=Developer` уже стоит в «Доверенных лицах». Старой версии
  нужен запущенный LGSTrayBattery.
- Код: тег `before-loggybat` — состояние до перехода.

    - Logitech G502 X PLUS
    - Logitech PRO X WIRELESS

    Поддержка других моделей не проверена и не гарантируется.
    Техника, которую не видит G HUB, не поддерживается.

    ## Первая установка

    > **Важно: пакет подписан самоподписанным сертификатом разработчика** (`CN=Max`),
    > а не через Microsoft Store. Чтобы Windows разрешила установку, этому сертификату
    > нужно доверить — добавить его в «Доверенные лица» компьютера (нужны права
    > администратора). Делайте это, только если доверяете источнику.

    1. Установите **WidBar** из Microsoft Store:
       https://apps.microsoft.com/detail/9PKLDNM83TP9
    2. Установите **Logitech G HUB** с сайта Logitech:
       https://www.logitechg.com/software/ghub
       — и убедитесь, что G HUB видит ваши устройства.
    3. Скачайте и установите **LoggyBat**: комплект первой установки из раздела
       [Releases](https://github.com/mrmaxxxx/LoggyBat/releases/latest),
       далее — по инструкции в описании релиза (включая доверие сертификату).
    4. Добавьте виджет в WidBar: **Layout → Refresh → LoggyBat**.

    ## Обновление

    Если LoggyBat уже установлен, шаги первой установки повторять не нужно:

    1. Скачайте из [Releases](https://github.com/mrmaxxxx/LoggyBat/releases/latest)
       только файл `LoggyBat…_x64.msix`.
    2. Закройте WidBar полностью (иначе Windows не заменит файлы виджета).
    3. Установите пакет в PowerShell:
       `Add-AppxPackage -Path "<путь>\LoggyBat…_x64.msix"`
    4. Запустите WidBar — виджет останется на прежнем месте.

    - **Уже установлен?** Скачайте только `LoggyBat…_x64.msix` — это обновление.
